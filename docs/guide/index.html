Sources have
different jobs.

A repository record, an identity registry and a semantic search result offer different kinds of evidence. A successful lookup establishes access; it does not by itself prove where a final property came from.

↗

Software & repository facts

GitHub REST and account data supply handles, ownership and repository metrics. GIMIE contributes repository metadata. Hugging Face and RenkuLab are available through indexed research tools.

≈

People & organizations

ORCID and ROR help resolve identity and affiliation. A GitHub handle remains useful evidence, but an identity match and a copied property are different claims.

§

Publications & research outputs

Infoscience, ETH Research Collection, OpenAlex and Zenodo provide scholarly context. SNSF and SWISSUbase broaden the available indexed research sources.

∈

Disciplines & web context

EPFL Graph supports discipline search. Optional concept tagging and enabled search/browser tools add context. Availability depends on configuration, credentials and index state.

Records carry facts; vectors find candidates.

DuckDB holds indexed records for hydration. Qdrant supports vector similarity search. A search hit is a route to evidence, not a replacement for the source record.

Embedding and extraction are different jobs.

An embedding model encodes text for retrieval. An extraction LLM reasons over context and tools to produce structured entities. Their configuration and costs are separate.

Index ingest, embedding and reset belong to open-pulse-sources. This repository owns extraction and read-side integration. The diagrams describe available paths, not a promise that every request queries every source.

Change one mapping.
Keep its meaning.

Small packaged YAML files describe deterministic fields. Python owns fetching, matching, normalization and graph algorithms. YAML alone does not add a provider or a pipeline stage.

A real field, with a deliberate source

# mapping/config/raw/repository.yaml (excerpt)
schema_version: 1
name: raw.repository
version: '2'
source_contract: extractor.v2.entity
target_contract: raw.repository
fields:
  pulse:watcherCount:
    sources: [_subscribers_count]
  schema:url:
    sources: [_homepage]
    transform: web_iri

An excerpt to edit in place, not a replacement for the complete mapping.

Why this mapping is correct

GitHub subscribers_count means watchers. Its confusingly named watchers_count means stars. A type check cannot detect that semantic error.

sources is an ordered fallback list. Zero and false count as data. web_iri accepts explicit HTTP(S) URLs and wraps them as an @id reference; it omits invalid links.

Choose one of sources or value. Targets must exist in a generated contract. Duplicate keys, unknown transforms and conflicting nested targets fail validation.

For an agent JSON Schema change

Edit the authoritative agent or strict schema under git_metadata_extractor/schema/json/. The generator reads this source directly. Files under tests/v2/fixtures/schema/ are example payloads, not duplicate schemas.

Run just v2-models-generate and just v2-models-check. Preserve the pinned generator toolchain. Update the generated contract and its mapping in the same change.

A cache hit is its own outcome

A pipeline cache hit returns status: "cache_hit". It does not invent new stage executions or model calls. The request run and the run that produced the cached output can differ.

When usage is incomplete, totals are known subtotals. Attribution counts trace claims; they are not a factual-correctness score or a measure of final-graph coverage.

Observation does not launch provider work. The report remains a response sibling, alongside any separate evidence, extraction-run or substrate artifacts.
