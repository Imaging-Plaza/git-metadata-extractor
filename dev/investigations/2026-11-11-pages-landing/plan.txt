Landing page and GitHub Pages publishing

User request: make the visual guide the landing page, with reference docs in
a subsection of the same GitHub Pages site.

Design: preserve existing Markdown source paths and Mike version history.
Build a curated Pages artifact: visual guide at /, reference docs at /docs/,
and published versions at /docs/<version-or-alias>/. /docs/ redirects to latest
(then stable/first version as a fallback) in the versioned artifact. Local
preview builds ordinary reference docs directly at /docs/.

The current Pages setting points to gh-pages:/docs, which is source Markdown;
the existing publisher writes Mike output at the branch root. Switch to the
official GitHub Actions artifact publisher. Keep gh-pages as Mike's version
archive, but export only versions declared in versions.json, never unrelated
files from that mixed-content branch. Export aliases as real copies because
Pages artifacts cannot contain symlinks. A tag must not downgrade the landing
page: workflow assembles it from main, while publishing the tagged reference.
