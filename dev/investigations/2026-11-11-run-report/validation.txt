Compatibility and data handling

The extracted graph and ontology contracts are unchanged. Report selection does
not alter the semantic pipeline cache key or trigger fresh extraction. Cached
responses never store this per-request report; a cache hit returns a fresh reuse
summary with its own request ID, the original output ID and no claimed current
stage/model work. Default HTTP responses omit the report.

Report changes contain counts and property names, not values. Sources omit
userinfo/query/fragment components. Prompt bodies, provider bodies, raw query
arguments and exception messages are not copied. Usage distinguishes current
model calls from historical/imported evidence, with explicit completeness flags.
No secret-bearing files were changed.

Review

Independent review found one blocker: adapters returning structured failures
were recorded as completed because they did not raise. Explicit stage-outcome
annotation now handles those counters. Added mixed/all-failed and valid-negative
controls; reviewer confirmed the fix and found no remaining blockers in default
omission, cache semantics, usage, isolation, redaction or typed failure reports.

Limits and follow-ups

- This is structured JSON/API observability, not an HTML dashboard or telemetry
  backend. No new infrastructure, deployment or live-provider calls were made.
- Unexpected framework exceptions and cancelled jobs do not gain a new durable
  report store; typed domain failures after run initialization do carry reports.
- Optional snapshots and report serialization add work and response size only
  when enabled. Existing evidence collection is otherwise unchanged.
- Stage completion means the function completed, not that every optional side
  effect (such as a configured store write) ran. Validator conformance and child
  activity outcomes must be interpreted separately.
- Auxiliary failures without structured counters are not guessed from warning
  text. Attribution counts trace claims, not guaranteed final-field coverage;
  retrieval alone does not establish derivation or correctness.
- Legacy stats.stages_completed remains a compatibility summary. The optional
  observed timeline is the accurate execution surface.
