The missing proposal files under dev/v4.0.0, dev/ontology-v3-profiles and

preserved. import-manifest.json names every imported/preserved path and hash.

In evidence paths below, TTL means
vendor/open-pulse-ontology/src/ontology/, GME means git_metadata_extractor/,
and mapping means git_metadata_extractor/mapping/config/.

Classification: already adopted; partially supported; requires ontology
change; evidence-only (a useful alternative or finding, not approved runtime
vocabulary). Partial support does not authorize silently substituting a term
with different semantics. The matrix describes the baseline and distinguishes
the narrow runtime corrections in this integration from future work.

Narrow runtime integration and deferrals

The runtime integration is limited to retaining normalized source metadata
privately for substrate projection, restricting GitHub extras to GitHub
profiles, removing an unsupported ORCID biography fallback, and removing the
programming-language-to-natural-language mapping. These restore source and
ontology semantics without introducing experimental terms. Regression tests
exercise the actual JSON-LD/substrate stages, private metadata removal, source
separation, normalized references, and pinned raw SHACL conformance.

Restoring source fields also exposed bare web/Twitter values becoming relative
RDF IRIs. Raw URL mappings now use web_iri, which requires an explicit HTTP(S)
URL and validates/normalizes it through Pydantic. Bare Twitter handles are no
longer projected into pulse:socialLink. Mapping versions are bumped to 2 for
raw.repository, raw.person_profile and raw.organization_profile.

Existing schema:email attribution remains unchanged and needs a separate
source-aware design: the reconciled email may originate in context or GitHub,
so assigning it exclusively to either profile would invent source certainty.

All other runtime additions are deferred, even if compatible: externalReference
URLs; existing readme/fundingConfig/isTemplate/platform ID slots; extra entity
families; external schema.org normalization. Further upstream work should
prioritize version-aware packages, git identity multiplicity, affiliation kinds
and raw Project support. No TTL change, pin change or SHACL loosening is part
of this integration.
